# Purrdoku（各就喵位）游戏设计与玩法

本文从《微信小游戏综合说明》中抽出游戏本体：规则、操作、模式、提示、难度、成长和出题。不涉及界面布局、绘制、线程、存储实现或包体技术。

读者对象是设计、关卡和玩法实现。读完后应能独立说明：玩家要做什么、怎样算赢、怎样算错、提示为什么这样给、连续闯关为什么越来越难。

---

## 1. 游戏是什么

Purrdoku，中文名「各就喵位」，是一款单人逻辑解谜。棋盘是 `N×N` 彩色区域图。玩家在格子上做排除笔记、放置猫咪，直到满足全部规则。

它不是动作游戏，也不是限时闯关。没有生命值，没有倒计时失败，没有提示收费。玩家可以随时停下，下次从同一题继续。

核心一句话：

> 每行、每列、每个颜色区域恰好一只猫，任意两只猫不能相邻。

相邻包含上下、左右和斜对角，也就是中心格周围八格。远距离对角可以同时放猫。

---

## 2. 设计原则

| 原则 | 含义 |
| --- | --- |
| 轻松可中断 | 切后台、关游戏、打开说明都不会让当前题失败 |
| 即时核对答案 | 放猫立刻对照唯一答案，对了留下猫，错了记失误 |
| 笔记可逆 | `×` 是玩家笔记，不是已经证明的结论，可以取消 |
| 提示可解释 | 优先给出能讲清的推理；讲不清时明确说「直接揭示」 |
| 难度由题目结构决定 | 用时、提示、失误不改变下一题难度 |
| 每题恰好一解 | 新题必须能被支持的逻辑规则完整解出，且独立搜索确认唯一 |

当前产品不做：账号、云存档、联网排行榜、广告、付费、体力、生存模式、历史题目列表、手动选难度。首页也不再提供旧关卡花园或独立无限模式二级入口。

---

## 3. 核心规则

### 3.1 棋盘与区域

设边长为 `N`。当前正式尺寸是 6、7、8、9。

棋盘必须同时满足：

- 一共 `N×N` 格，全部有颜色区域。
- 每格恰好属于一个区域。
- 恰好 `N` 个非空区域。
- 每个区域四邻接连通，即上下左右相连，斜接不算连通。
- 存在且仅存在一个合法放猫方案。

区域颜色只表示归属，不表示难度。紫色区域和黄色区域在规则上完全对等。

两类邻接不要混用：

| 对象 | 邻接方式 | 用途 |
| --- | --- | --- |
| 颜色区域 | 四方向 | 判断一块颜色是否连成一片 |
| 猫咪 | 八方向 | 判断两只猫是否太近 |

### 3.2 胜利条件

最终要放 `N` 只猫，同时满足：

1. **每行恰好一只。**
2. **每列恰好一只。**
3. **每个颜色区域恰好一只。**
4. **任意两只猫不相邻。** 上下、左右、斜对角都不允许。

禁止的是「紧挨着的斜对角」，不是整条对角线。例如 6×6 上，`(0,0)` 和 `(1,1)` 不能同时放猫；`(0,0)` 和 `(2,2)` 可以。

不必把所有非答案格都标成 `×`。找齐 `N` 只正确的猫即可通关。

### 3.3 即时答案核对

玩家尝试放猫时，系统对照关卡保存的唯一答案：

- 位置属于答案：该格变成猫。
- 位置不属于答案：该格变成错误 `×`，当前失误加 1。

因此会出现一种「局部看起来合法、全局仍算错」的情况：当前已放的猫并不冲突，但这格不是最终答案。游戏仍然立刻判错。

原因：每题已证明恰好一解。一个暂时不冲突的位置，最终一定会和其他约束打架。即时核对避免玩家沿着错误分支走很远。

判错不会结束游戏。玩家可以撤销、重来或继续在其他格子推理。

### 3.4 一个 6×6 直觉例子

想象棋盘被分成 6 块彩色区域。玩家的工作不是「随便摆 6 只猫」，而是同时满足四套约束：

- 第 1 行已经有猫，第 1 行其余格子都不能再放。
- 这只猫所在的列、所在颜色、周围八格同样不能再放。
- 某个颜色如果只剩一格还能放，那一格就必须是猫。
- 如果某颜色剩下的候选全挤在第 3 行，那么这只猫一定占第 3 行，第 3 行其他颜色的候选可以排除。

玩家通常先标 `×` 缩小候选，再在只剩一格时放猫。

## 4. 格子状态

每格四种状态：

| 状态 | 玩家含义 | 能否点按切换 | 拖动会不会覆盖 | 再放猫 |
| --- | --- | --- | --- | --- |
| `empty` | 还没判断 | 可标成 `×` | 可被标成 `×` | 可以尝试 |
| `markedX` | 排除笔记 | 可取消回空白 | 不会再覆盖 | 可以尝试 |
| `cat` | 已核对正确的猫 | 不能点掉 | 不能覆盖 | 无效，不移除 |
| `wrongX` | 这里放错过猫 | 不能点掉 | 不能覆盖 | 仍算一次失误 |

补充：

- 普通 `×` 只是笔记。自动标记写下的 `×` 也一样，不代表系统已经证明该格不可能。
- 错误 `×` 是成绩记录的一部分。要拿掉只能撤销，不能单击擦除。
- 再次双击已经判错过的格子，仍增加一次失误。
- 正确的猫一旦落下，就不能用单击、拖动或再次放猫拿掉；只能撤销整步。

## 5. 玩家操作

所有模式共用同一套棋盘操作。手机以触摸为主，支持键盘的微信电脑端另有等价命令。

### 5.1 单击：切换排除笔记

对空白格单击一次，写成 `×`。对普通 `×` 再单击一次，取消回空白。

这是最常用的推理动作：把「这里不可能有猫」记下来。

判定规则：

1. 手指在同一格按下并抬起，进入「待定单击」。
2. 220 毫秒内没有第二次同格触摸，才真正提交这次标记。
3. 若 220 毫秒内同格再次按下，取消待定单击，改走双击放猫。
4. 快速点不同格子时，先提交上一格单击，再开始新格判断。

220 毫秒只用于区分单击和双击，不进入游戏随机序列，也不影响出题。

### 5.2 双击：尝试放猫

同格两次触摸，且第二次没有滑去其他格子，执行放猫。

结果：

- 正确：格子变成猫。若开启自动标记，同时排除相关空白格。
- 错误：格子变成红色错误 `×`，当前失误加 1，游戏继续。

已有正确猫的格子再放无效。已有错误 `×` 的格子再放仍加失误。

### 5.3 拖动：连续标记

手指跨到另一格后，整段手势变成拖动：

- 取消这次可能产生的单击或双击。
- 从起始格开始，把沿途空白格预览标成 `×`。
- 正常抬手后，一次性提交整笔标记。
- 已有猫、普通 `×`、错误 `×` 都不会被拖动改写。

为避免快速滑动漏格，路径按格子中心做插值：

```text
steps = max(|终点行 − 起点行|, |终点列 − 起点列|)

第 s 步取：
  行 = round(起点行 + Δ行 × s / steps)
  列 = round(起点列 + Δ列 × s / steps)
```

横向、纵向是主要用法，实现不锁死方向，转折和斜向路径也有效。

以下情况丢弃未提交预览，不写入撤销历史：

- 系统取消触摸
- 切到后台
- 打开会挡住棋盘的弹层
- 窗口或布局变化

不要把系统取消当成正常抬手。否则可能出现「手指已经离开，棋盘却留下一串 ×」。

### 5.4 键盘与鼠标（电脑端）

在平台确实提供键盘时：

| 按键 | 作用 |
| --- | --- |
| 左 / 右 | 焦点左右移动 1 格，允许跨行 |
| 上 / 下 | 焦点按棋盘边长 `N` 移动，即换行 |
| 越出边界 | 截断到合法格子，不环绕 |
| 空格 | 切换当前格的 `×` |
| Enter | 尝试在当前格放猫 |

鼠标映射到同一套命令，不能键盘和鼠标各处理一次导致重复提交。弹层打开时，棋盘不接收这些按键。

手机外接键盘不承诺可用。

### 5.5 辅助命令

| 命令 | 玩法效果 |
| --- | --- |
| 撤销 | 回到上一步棋盘和当前失误 |
| 提示 | 生成可阅读的下一步计划，确认后才改棋盘 |
| 重来 | 同一题从头再下 |
| 规则说明 | 只讲解规则，不改棋盘 |

这些命令不改变题目本身。

## 6. 自动标记

默认开启，所有模式共用。可在设置中关闭。

正确放下一只猫后，把下列空白格标成 `×`：

- 同一行
- 同一列
- 同一颜色区域
- 周围八格

不覆盖已经是猫、普通 `×` 或错误 `×` 的格子。

设计意图：把「这只猫已经占用的空间」立刻清掉，减少重复劳动。它仍然只是笔记。若玩家关了自动标记，就要自己做这些排除。

放猫和随后的自动标记算同一次编辑。撤销一次，猫和这批 `×` 一起回去。

提示应用导致放猫，或系统直接揭示答案格时，同样遵守该开关。

## 7. 撤销与重来

### 7.1 撤销

快照内容：当时的整盘格子，以及当时的当前失误数。最多保留最近 100 步。

| 玩家动作 | 算几步 |
| --- | --- |
| 单击标记或取消 | 1 步 |
| 一次拖动整笔提交 | 1 步 |
| 放猫 + 自动标记 | 合并 1 步 |
| 一次提示应用（含它引起的自动标记） | 全部目标变化合并 1 步 |

撤销不回退：

- 已经走过的用时
- 提示使用次数
- 连续闯关里本题的累计错误

通关后禁止再撤销改成绩。

### 7.2 重来

同一题重新开始，但两种模式的记账不同。

连续闯关重来：

- 题目和关号不变
- 棋盘清空
- 当前失误清零
- 本次用时清零
- 撤销历史清空
- 本题累计错误、累计提示、累计用时保留
- 重来次数加 1

每日挑战和普通静态题重来：

- 创建一次新的本关会话
- 历史最好成绩保留

「当前失误」和「累计错误」不是一回事。前者可撤销、可因重来清零，并决定当前星级；后者只增不减，用于无失误完成统计。

## 8. 计时、星级与成绩

### 8.1 何时计时

只在同时满足时累计用时：

- 游戏场景可见
- 当前题尚未完成
- 没有挡住操作的弹层
- 允许玩家操作棋盘

切到后台暂停。回到前台后从新的主动计时基准继续，不把后台时间补进来。

连续闯关在下列情况也暂停：

- 还在等第一题
- 正在读取恢复数据
- 正在计算提示

### 8.2 星级

由**当前失误**决定，不是累计错误：

| 当前失误 | 星级 |
| --- | --- |
| 0 | 三星 |
| 1–2 | 两星 |
| ≥3 | 一星 |

因此：

- 放错一次再撤销回去，当前失误回到 0，仍可拿三星。
- 但本题累计错误已经不是 0，不能记入「无失误完成」。

三星 ≠ 生涯统计里的无失误完成。

### 8.3 通关后发生什么

找齐 `N` 只正确的猫即完成。完成时锁定本题成绩：不能再改棋盘、不能再撤销刷星。

连续闯关不会自动跳下一关。玩家看完结果后，手动进入下一关。下一关使用预先准备或即时生成的新题，关号加 1。

刷新页面、重来、撤销、使用提示都不会推进关号。

### 8.4 长期统计

每次完成一个游玩实例，最多记三类计数，且只记一次：

| 统计 | 条件 |
| --- | --- |
| 完成 | 本题通关 |
| 独立完成 | 通关时提示次数为 0 |
| 无失误完成 | 通关时本题累计错误为 0 |

里程碑关会留下旅程纪念，不改变棋盘规则，也不提高难度。

## 9. 游戏模式

两种正式入口共用规则、提示、自动标记和设置，只在出题与存档上不同。

### 9.1 连续闯关

首页「开始游戏」。这是主线。

- 没有当前题时，发放开场题。
- 有当前题时，恢复同一道题和进度。
- 新请求由生成器 V5 出题，尺寸为 6×6 到 9×9。
- 显示的难度是这道题实际评出的档位：轻松、标准、困难、专家。
- 通关后手动进下一关。
- 难度随关号、近期发挥和保护规则变化，玩家不能手动选难度。

内部实现可仍叫 `InfiniteMode`，对玩家就是连续闯关。

### 9.2 每日挑战

按设备本地日期 `YYYY-MM-DD` 从内置静态题里选题，不是每天现场生成。

选题方式：把日期字符串逐字符哈希，再对静态题数量取模。同一天、同一份静态题库，得到同一道题。

- 会话按日期独立保存。
- 当天没打完，下次还能继续。
- 零点不会强行换掉正在玩的题。下次从每日入口进入时，才按当时日期选题。
- 展示文案沿用「轻松」，不表示这题已经过 V5 评分。
- 最好星级取历史最大值，最好用时取历史最小值。两者独立更新，可能来自不同次游玩。

### 9.3 静态关卡的位置

产品保留 10 道 6×6 内置题，供每日挑战和旧数据兼容。首页不再单独做「关卡花园」或手动选关菜单。保留兼容能力，不等于再给玩家一个选关入口。

## 10. 提示系统

提示是可选辅助，不是关卡脚本。不用提示可以通关，用了就不能记独立完成。

### 10.1 先预览，再应用

系统先生成一份只读计划，不改棋盘。玩家看懂后确认应用，才真正编辑。

计划包含：

- 类型：放猫、排除、纠错、直接揭示
- 标题和原因
- 目标格子
- 推理依据格子
- 当时棋盘指纹，防止看提示期间棋盘已变
- 涉及的行、列或区域（若有）

有效提示一旦展示就计数。计算失败、被取消、还没形成可读提示，不计次。关掉提示窗口仍算用过。之后撤销应用，次数也不退回。

### 10.2 选择顺序

始终按这个顺序找下一步，不因设备快慢改顺序：

1. **纠错。** 若答案格被玩家标成普通 `×`，先指出这个错误。文案必须说明核对了答案，不能假装是纯推理。
2. **直接传播。** 已放的猫周围，若还有按规则应排除的空白格，先帮玩家标掉。
3. **可解释逻辑。** 把当前猫和已经检查过的标记交给逻辑求解器，取第一步能讲清的操作。
4. **直接揭示。** 没有简短推理时，明确放一只答案猫，并说明这不是纯推导。

普通 `×` 在进入第 3 步之前必须先经过纠错。因为笔记可能本身就是错的，不能把错笔记当成前提。

### 10.3 四种提示

| 类型 | 玩家看到的结果 | 何时出现 |
| --- | --- | --- |
| 纠错 `correct` | 取消误标在答案上的 `×` | 答案格被笔记排除 |
| 排除 `exclude` | 给一个或多个空白格标 `×` | 从已放猫传播，或 B3 / B4 / C1 |
| 放猫 `place` | 在逻辑上已确定的格子放猫 | 通常对应 B1：某行、列或区域只剩一格 |
| 揭示 `reveal` | 直接放一只答案猫 | 当前没有能用短规则说明的下一步 |

应用提示时若开启自动标记，放猫仍会带上自动排除，整次变化只占一步撤销。

应用前还要确认：还是同一道题、棋盘没被改过、题目未完成、仍允许编辑。条件不满足则丢弃这份计划。

### 10.4 提示文案原则

- 能用行、列、颜色讲清的，就讲清。
- 纠错必须承认查了答案。
- 揭示必须承认不是推理。
- 不为了显得「更聪明」而把揭示包装成伪推理。
- 不保证每一题的每一步都能纯推理解释。卡在支持规则之外时，揭示是合法出口。

## 11. 玩家实际在用的推理

提示和出题共用同一套逻辑规则。玩家不必知道编号，但关卡保证能用这些规则解完。

求解时把棋盘看成 `3N` 个单元：`N` 行、`N` 列、`N` 个区域。每格同时属于一行、一列、一个区域。规则按固定顺序反复套用，一旦局面有变化，立刻从头再走基础规则。

### 11.1 B1 唯一候选

某行、某列或某颜色只剩一个还能放猫的格子，这里必须放猫。

这是最常见的「看出来了」：一块颜色被挤到只剩一格。

### 11.2 B2 直接传播

已经确定的猫，会排除：

- 同行
- 同列
- 同颜色
- 八方向相邻格

自动标记做的就是把 B2 写到棋盘上。关闭自动标记时，玩家通常要自己做这一步。

### 11.3 B3 区域与直线锁定

一个单元剩下的候选，全部落在另一个相交单元里，则后者多出来的候选可以排除。

只处理「区域 ∩ 行」或「区域 ∩ 列」，不处理任意两个单元。两行之间、两列之间、两块颜色之间，不直接套 B3。

例子：绿色区域还剩的格子全在第 4 行。那么绿猫必占第 4 行，第 4 行里不属于绿色的候选都可以标 `×`。

### 11.4 B4 必然相邻排除

某格虽然自己还空着，但和一个「必有猫」单元的所有候选都相邻。无论那只猫落在哪个候选上，都会和这格打架，所以这格可以排除。

例子：第 2 列还剩 `(1,1)` 和 `(2,1)`。格子 `(1,2)` 与这两个候选都相邻，则 `(1,2)` 不可能有猫。

### 11.5 C1 两组占满两组

两个来源单元的候选，只覆盖两个目标单元。这两只猫必然占满那两个目标，其他来源在这两个目标里的候选可排除。

只允许这四种配对：

- 两个区域 → 两行
- 两个区域 → 两列
- 两行 → 两个区域
- 两列 → 两个区域

例子：黄区和绿区的猫都只能落在第 2、3 行。它们必然占满第 2、3 行，其他颜色在这两行里的候选可排除。

不做到三组、四组组合，也不把猜测回溯包装成可解释规则。前十关故意禁止依赖 C1，让玩家先熟悉 B1–B4。

### 11.6 和「唯一答案」的关系

上述规则用于：

- 证明新题能纯逻辑解完
- 给提示提供可讲解步骤
- 给难度评分提供推理轨迹

另有一套独立搜索：按行选列，维护已用列、已用区域，以及与上一行猫是否相邻。只需看上一行，因为再往上的行距离已经大于 1，不可能八方向相邻。

只有完整搜完且恰好一个解，这题才能过关。发现第二解、零解、搜到一半超预算，都不能当正式题。

对玩家的意义是：盘面上看到的每个最终放猫位置都是被迫的，不存在「另一种也算对」的摆法。

## 12. 关卡必须长什么样

### 12.1 结构硬条件

每一道正式题都要：

- 全盘覆盖，无空洞、无重叠区域
- 恰好 `N` 个连通区域
- 声明答案本身符合四条玩法规则
- 独立搜索确认唯一解，且等于声明答案
- 新题能被支持的逻辑规则解完，不能只靠猜

### 12.2 形状可读性

避免区域细碎、细长走廊或过度凹陷，让棋盘「看得清」：

| 指标 | 轻松题 | 其他难度 |
| --- | --- | --- |
| 单格区域数量 | 最多 1 个 | 0 个 |
| 最大区域面积 | ≤ `3N` | ≤ `3N` |
| 单格宽直走廊最长长度 | ≤ 4 | ≤ 5 |
| 单区域最多凹角 | ≤ 7 | ≤ 9 |
| 最大周长比 | ≤ 1.85 | ≤ 2.0 |

周长比：

```text
区域周长 / (4 × sqrt(区域面积))
```

凹角：某个网格顶点周围四格中，恰好三格属于该区域。

细走廊：沿某方向连续、且垂直方向没有同区邻居的单格宽细段。不是所有区域边缘都叫走廊。

这些约束管的是形状极端程度，不直接等于「难不难」。轻松题允许一个单格区域当教学，其他难度不允许再出现单格区域。

### 12.3 题目数据里和玩法有关的内容

玩家能感知或成绩依赖的部分：

| 内容 | 作用 |
| --- | --- |
| 边长 `N` | 猫的数量、行列数量 |
| 区域矩阵 | 颜色划分 |
| 答案坐标 | 放猫对错、提示纠错与揭示 |
| 难度档位 | 连续闯关显示轻松 / 标准 / 困难 / 专家 |
| 评分细节 | 决定档位，玩家不直接看到公式 |
| 来源 | 现场生成、开场池题或预算耗尽后的备用池 |

完整题目会保存在进度里。不能只存一个种子，下次打开再随机出一次。否则玩家恢复时会拿到另一道题。

## 13. 难度如何计算

连续闯关显示的难度，来自 V5 综合轨迹评分，不是出题时随口起的名字。

理论分 0–100。主线目标硬上限 78，即正式发放不会追求满分专家题。

请求里的 easy / normal 只是生成时的结构策略。最终档位以评分为准。

### 13.1 五项指标

先走一遍逻辑求解，记下有效排除轨迹，再评分。

| 指标 | 含义 | 最大贡献 |
| --- | --- | --- |
| B | 棋盘尺寸：`clamp((N−6)/3, 0, 1)` | 10 |
| F | 放下第一只猫之前，有效排除步数 | 25 |
| R | 首猫之后，两次落猫之间最长的有效排除链 | 20 |
| C | 有效 C1 组合排除次数 | 30 |
| W | 其余有效排除的工作量：`max(0, D−F−R)/N` | 15 |

`D` 是总有效排除步数，本身不直接加分，只进入 `W`。

**有效排除**必须真正删掉候选，且不是 B1、B2。也就是：B3、B4、C1 这类「需要想一下」的排除才计分。

不算分的包括：

- B1 落猫
- B2 常规传播
- 没有改变候选的空操作

`F` 不重复计入 `R`。第一只猫之前的排除只进开局难度，不进中段最长链。

### 13.2 从原始次数映射到 0–1

各点之间线性插值，结果限制在 0–1。

| 指标 | 输入 → 归一化 |
| --- | --- |
| F | 0→0，1→0.15，2→0.30，4→0.60，6→0.85，8→1 |
| R | 0→0，1→0.20，2→0.35，4→0.65，6→0.85，8→1 |
| C | 0→0，1→0.35，2→0.60，3→0.80，4→1 |
| W | 0→0，0.5→0.35，1→0.70，1.5→1 |

```text
加权分 = round(10B + 25f(F) + 20f(R) + 30f(C) + 15f(W))
最终分 = min(100, max(语义下限, 加权分))
```

### 13.3 语义下限

某些结构一旦出现，分数不能再低到「看起来很简单」：

| 条件 | 最低分 |
| --- | --- |
| C≥1，或 F≥3，或 R≥4 | 25 |
| C≥2，或 F≥5，或 R≥5 | 45 |
| C≥3 | 65 |

档位：

| 分数 | 玩家看到的名称 |
| --- | --- |
| 0–24 | 轻松 |
| 25–44 | 标准 |
| 45–64 | 困难 |
| 65–100 | 专家 |

公式示例（只说明计算，不是某道固定真题）：7×7，轨迹 `F=2`、`R=3`、`C=1`、`D=8`。则 `B=1/3`，`W=3/7`。五项大约是 3.33、7.5、10、10.5、4.5，合计 36 分，属于标准。

### 13.4 再难也有硬顶

全局还限制轨迹不能无限堆规则：

- `F≤10`
- `R≤10`
- `C≤6`
- 6×6 / 7×7：轻松题 `D≤12`，其他 `D≤20`
- 8×8 / 9×9：`D≤30`

教学关、放松关、新尺寸适应关还会更严。

### 13.5 评分不是成绩预测

分数描述「这题的逻辑轨迹有多陡」，不是预测玩家要用多久。

同一题做旋转、镜像或换色后，前五关、放松关、里程碑关会检查评分跨度：八种变换再加一次反向色号，最高分与最低分之差不能超过 15。这是防止扫描顺序把同一结构评得忽高忽低，并不表示每个方向分数完全相同。

玩家在上一题用了多久、用了几次提示、犯了多少错，都不会拿去调下一题。节奏保护看的是题目本身的分数、尺寸和用途，不是玩家表现。

## 14. 连续闯关的成长曲线

主线不是「每关都比上一关难」，而是一条有起伏的长期曲线：教学 → 引入新尺寸 → 常态 / 挑战 / 放松交替 → 用保护规则避免连砸专家题。

棋盘最大 9×9。第 1000 关不会被规定成最难题。

### 14.1 关号与分数窗口

| 关号 | 常态分 | 挑战分 | 放松分 | 基础尺寸 |
| --- | --- | --- | --- | --- |
| 1–5 | 0–18 | 不随机安排 | 不随机安排 | 6×6 100% |
| 6–10 | 10–30 | 不随机安排 | 不随机安排 | 6×6 100% |
| 11–20 | 18–30 | 30–40 | 10–17 | 6×6 60%，7×7 40% |
| 21–40 | 25–38 | 38–48 | 15–24 | 7×7 100% |
| 41–70 | 30–44 | 44–55 | 20–29 | 7×7 70%，8×8 30% |
| 71–100 | 35–50 | 50–62 | 22–34 | 8×8 100% |
| 101–150 | 38–55 | 55–68 | 24–37 | 8×8 85%，9×9 15% |
| 151–200 | 40–58 | 58–72 | 25–39 | 8×8 70%，9×9 30% |
| 201 起 | 35–64 | 60–78 | 20–34 | 8×8 75%，9×9 25% |

201 关之后，挑战题的尺寸改为 8×8 60%、9×9 40%。

### 14.2 常态、挑战、放松

三种「用途」决定这题往窗口的哪一段靠：

| 阶段 | 常态 | 挑战 | 放松 |
| --- | --- | --- | --- |
| 1–10 | 100% | 0% | 0% |
| 11–100 | 70% | 20% | 10% |
| 101–200 | 65% | 20% | 15% |
| 201 起 | 60% | 25% | 15% |

保护规则会改写最终比例，不保证每十关固定几道挑战题。

放松题另外偏向较小棋盘，让玩家换口气：

| 阶段 | 放松尺寸 |
| --- | --- |
| 第 40 关及以前 | 6×6 70%，7×7 30% |
| 41–100 | 7×7 70%，8×8 30% |
| 100 关之后 | 7×7 20%，8×8 80% |

实际选择还会滤掉「还没接触过的尺寸」以及「不能连续大棋盘」。

### 14.3 前十关教学

前十关禁止 C1，避免一上来就做组合占位。

| 关号 | 额外限制 |
| --- | --- |
| 1–5 | `F≤1`，`R≤2` |
| 6–10 | `F≤3`，`R≤4` |

教学写在题目结构里，没有强制「先点这一格再点那一格」的操作脚本。

### 14.4 新尺寸适应

尺寸按接触顺序逐步出现。每个新尺寸前两次发放视为适应题：

- 通常改成常态用途
- `F≤3`
- 分数硬上限不超过「当前阶段常态上限」和 50 中的较小值
- 若同时触发连续难题保护，保护优先

「接触过几次」按实际发到玩家手上的次数计，不编造历史。

### 14.5 节奏保护

在抽完用途和窗口之后，再用保护规则改写，避免体验上的猛撞或连续过易：

| 近期情况 | 下一题怎么处理 |
| --- | --- |
| 连续三题实际分数 ≥ 60 | 强制放松，硬上限 ≤ 34 |
| 最近四题至少两题 ≥ 65 | 硬上限 ≤ 59；若抽中挑战则改常态 |
| 上一题已经是放松，这题又抽到放松 | 通常改回常态；真正的硬保护仍可覆盖 |
| 连续两题 9×9 | 下一题不能再是 9×9 |
| 20 关之后连续三题 ≤ 30 | 避免继续随机放松，适用时提高常态下限 |
| 旧当前题无法评分 | 用常态较低区间过渡，硬上限 ≤ 59 |

低分保护盖不过教学、尺寸适应、连续难题这些更严的约束。

长期目标是「有起伏的稳定难度」：偶尔来一道更陡的挑战，偶尔放一口，而不是单调递增。

### 14.6 去重与纪念关

最近 20 道离开的题目，按规范化区域签名去重。旋转、镜像、整体换色视为同一题。长周期仍可能再遇到很久以前的结构。

纪念关：

- 第 25 关，以及 50 的倍数：小纪念
- 100 的倍数优先：大纪念

纪念改变装饰、记录和评分稳定性检查，**不提高难度**。棋盘操作与普通关相同。

## 15. 题目从哪里来

玩家不直接操作生成器，但生成规则决定「下一关摸到什么」。这里只保留玩法相关部分。

### 15.1 一次出题在做什么

1. 用个人种子、关号、生成版本和近期历史，算出用途、尺寸、分数窗口。
2. 开场关直接从本地题池挑合格题。
3. 其他关先随机生成：合法的猫布局 → 区域生长 → 修补多解 → 逻辑求解、评分、几何检查 → 唯一性与去重 → 必要时做变换稳定性。
4. 通过则成为当前题。
5. 计算预算用尽仍不合格，则在题池里按分数窗口补题。
6. 池里也没有合格题，则明确失败并保住当前进度，不会偷偷换成一道更简单或更难的题。

同一关号对两个玩家不必相同。个人种子不同，布局就不同。

### 15.2 先摆猫，再长颜色

第一步只决定 `N` 只猫的坐标：

- 每行一只
- 每列不同
- 与上一行的列号至少差 2，从而八方向不相邻

这时还没有颜色，也还没证明最终题面唯一。

第二步让每个答案格成为一块颜色的种子，向空白格四方向扩张，直到铺满。扩张偏好「多贴着自己、面积别太大」，保证每块颜色连通，且答案格不被改掉。

非轻松策略有时会在相邻两行预埋一对区域，给 C1 创造机会。最终仍必须被完整逻辑求解确认，不能只因为长得像组合题就算数。

### 15.3 多解怎么修

若搜索发现另一套也合法的放猫方案，生成器会试着改额外解里那些非答案边界格的颜色归属，让那套方案在区域规则上破产。答案格本身不动。最多修有限次，修完仍要独立验证「只剩声明的那一个解」。

对玩家而言：看到的题不应该存在第二种摆法。

### 15.4 备用题池

V5 冻结了 607 道规范题面，覆盖 160 种分数 / 尺寸窗口，每窗至少 32 道。同一题可以同时覆盖多个窗口。

池题用于：

- 前几关开场，保证第一印象稳定
- 现场生成达到固定计算预算仍失败时的兜底

挑池题时仍要满足当前硬上限、尺寸、逻辑限制、稳定性和近期去重。只允许在精确窗口找不到时，最多放宽 ±3 分。不会为了快点出题就放宽「必须唯一、必须能逻辑解完」。

选择由完整请求决定，不按当天时间随机，也不再随机换色。同一请求应得到同一道池题。

### 15.5 下一关何时出现

当前题还在玩时，系统最多预先准备 1 道下一题，不影响当前棋盘。

只有同时满足才换成下一题：

- 当前题已经完成
- 玩家确认进入下一关
- 关号和请求对得上
- 结果通过校验

没有当前题时，自动接收开场题。

等待出题不会让已有进度作废。超时或计算失败应允许重试同一请求，而不是因为某台手机慢就换一道别的题。

## 16. 进度怎样算「同一局」

### 16.1 连续闯关关号

新档关号进度为 0。接受第一题后变为 1，界面把这个值显示为当前关。计划下一题时用「当前值 + 1」。

下列行为不推进关号：

- 刷新或重新打开
- 重来
- 撤销
- 使用提示

### 16.2 一题里要记住的量

| 量 | 含义 |
| --- | --- |
| 当前失误 | 可撤销、可因重来清零，决定星级 |
| 累计错误 | 本题内只增不减 |
| 提示次数 | 有效提示展示次数，撤销不退 |
| 本次用时 | 当前这次尝试的主动操作时间 |
| 累计用时 | 同一题所有尝试加总（连续闯关重来后仍保留） |
| 重来次数 | 连续闯关重来计数 |
| 撤销历史 | 最近最多 100 步 |
| 是否完成 | 完成后锁定 |
| 是否已记入统计 | 防止同一通关写两次 |

完成状态、统计和里程碑在同一次结算里提交，避免「通关了但统计没加上」或「退出再进又加一次」。

### 16.3 节奏历史

连续闯关会记住最近约 20 道已经离开的题：实际分数、用途、尺寸、规范签名、各尺寸发过几次、纪念资格。当前正在玩的题单独保留，做下一题计划时再合并进去。

这些历史只服务于「下一题别太连难、别立刻重复、别连续 9×9」，不展示给玩家当成绩单。

### 16.4 设置里会影响玩法的项

| 设置 | 默认 | 对玩法的影响 |
| --- | --- | --- |
| 自动标记 | 开 | 正确放猫后是否自动写 B2 排除 |
| 游戏音效 | 开 | 仅反馈，不改变判定 |
| 背景音乐 | 关 | 仅氛围 |
| 触觉反馈 | 开 | 仅反馈；连续拖动不逐格振动 |
| 动态效果 | 开 | 仅表现；关掉后通关不等待庆祝动画 |

音效或振动失败不影响一次标记、放猫是否成功。设备静音时，编辑照样生效。

## 17. 一局标准流程

以连续闯关为例，玩家实际循环是：

1. 从首页进入，恢复未完成的当前题；没有则领取开场题。
2. 观察颜色区域，用单击和拖动标记不可能的格子。
3. 在只剩唯一位置，或有把握时，双击放猫。
4. 放对则猫留下，通常自动排除一行一列一区和周围八格；放错则记失误，可撤销。
5. 卡住时查看规则或请求提示。提示先预览，确认后才改盘。
6. 找齐 `N` 只猫，得到星级、用时、失误和统计。
7. 手动进下一关。系统按成长曲线给新尺寸、新分数窗口，并套用节奏保护。
8. 随时退出。下次打开仍是同一题、同一批笔记和同一份用时。

每日挑战把第 1 步和第 7 步换成「按今天的日期取静态题 / 没有下一关」，棋盘内操作完全相同。

## 18. 设计边界（玩法层面）

这些不是技术限制，而是玩法承诺：

- 没有限时失败，也没有「错三次本关作废」。
- 提示永远可用来过关，但会失去独立完成。
- 不靠猜测回溯过关；正式题应能被 B1–B4，以及（教学后）C1 解完。
- 不提供手动选难度。难度来自关号、评分和保护规则。
- 不把玩家表现反馈进下一题。打得慢不会被降难度，打得快也不会被加码。
- 不保证长周期永不重复旧结构，只保证近期 20 题不出现等价题面。
- 不保证每一步提示都是纯推理；揭示是明确标注的退路。
- 真人手感、耐玩性和「这题好不好玩」仍要靠试玩校准，分数公式不能替代。
